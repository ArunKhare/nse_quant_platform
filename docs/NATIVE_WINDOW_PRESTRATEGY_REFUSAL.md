# Audited native window-publication pre-strategy refusal

## Scope and accepted baseline

This additive package connects actual accepted research-window publication/admission
to a bounded native refusal-only decision consumer and exact original refusal replay.
It is not an admission-capture wrapper, architecture-only delivery or paper-loop extension.

- Decision codec: native-window-prestrategy-refusal@1.
- Recording: native-window-prestrategy-refusal-recording@1.
- Command: decide.native_window_prestrategy_refusal@1.
- Actual stage/inventory dependency: iron-condor-proposal-input-requirements@1.

User-confirmed QA through da1f9b1 is accepted/closed, with supplied matching HEAD/origin.
The preceding supplied 7784cfa has the same commit subject; no contents, full hashes or
commit relationship beyond supplied output are invented. Actual current sources were
retrieved, including accepted QA formatting/repairs. No accepted dependency is replaced.
No assistant repository/Git/worktree/Windows/uv inspection or push is claimed.

Production publication, real-data loading/migration, trust/identity/key/policy/authority
registration, trading and decision-loop cutover remain HELD. Disposable synthetic
fixtures are permitted. No positive decision contract or strategy implementation is added.

## Why a versioned native consumer is necessary

The inspected native refusal @1 explicitly decodes quote-publication admission receipts
and checks quote-specific dependency versions. Window publications cannot be inserted
there without changing that accepted contract or falsely relabeling source evidence.

The new profile reuses actual native_refusal_decision.RefusalRequest, request_document,
clock, canonical/strict JSON, safety _early/admission_may_be_observed helpers, runtime
observations and native_strategy_requirements stage/inventory. It uses actual native
AuditLedger and original native-refusal catalog/path helpers. Its new source-specific
adapter consumes actual legacy_window_admission APIs and decoder. Quote refusal @1,
old admission-capture profiles and legacy decision loop are unchanged.

This is a refusal-only sibling codec/recording, not a generic profile dispatcher or
an eligible-input bridge. The inspected source-only contract supports direct recording
of two actual policy observations; a separate window admission capture is not required
as a fabricated prerequisite. The complete receipts are retained in the refused entry.

## Request and ordering

RefusalRequest is the actual accepted native class, not a reconstructed replacement.
For THIS profile, expected_publication_evidence_fingerprint means the separately
reviewed WINDOW PUBLICATION RECORDING fingerprint, not its bundle ID or upstream Gold
fingerprint. publication_id identifies the accepted window-publication profile.
Both knowledge_cutoff and economic_at are mandatory aware request instants. Reviewed
code revision is a 40-hex execution label, not authenticated Git/build attestation.

The actual stage order is:

    kill_switch -> safety_boundary -> publication_admission -> native_inputs
    -> strategy -> portfolio_risk -> execution

ACTIVE or UNKNOWN kill switch refuses before source import/probe. INACTIVE is only an
explicit request observation, not an authenticated live-switch fact. The safety gate
then refuses live requests, non-dry-run or non-paper-only requests. Early/missing-source
refusal does not import window admission/publication services or probe source metadata,
paths or SQL. It still records/reads its dedicated output store and local code context.
An explicit absent source after safety yields WINDOW_ADMISSION_NOT_OBSERVED, not a
fabricated missing/ready native input or successful admission result.

If safety permits observation, the service calls actual assess_window_publication_use
with POINT_IN_TIME_DECISION and exact publication/recording pins TWICE. Both full encoded
receipts are retained and replayed. Exact request axes/publication identity must match;
full-byte drift is retained as a blocked admission outcome, never ignored as equal status.
Operational/corrupt source errors propagate and leave a failed recording job, not a
fabricated domain refusal pretending a policy observation occurred.

The accepted window policy always rejects point-in-time decisions. Matching REJECTED
receipts produce WINDOW_POINT_IN_TIME_ADMISSION_REJECTED plus original policy reasons.
A codec cannot import a supported positive admission; there is no such lane. A changed
reviewed pin is rejected by the actual pinned source API. Pure supplied receipt replay
is content computation only, not native evidence/authentication or permission.

PASSED trace entries mean the earlier REQUEST gates passed, not authenticated switch,
safety or market facts. All native_inputs/strategy/risk/execution stages remain NOT_RUN.
The input inventory is the actual direct-proposal inventory, NOT complete portfolio,
market-data or loop coverage. It is NOT_ADMITTED only when policy observations exist;
otherwise NOT_OBSERVED. No option-chain readiness, canonical identity or fabricated
portfolio inputs are asserted. strategy_evaluated, portfolio_risk_evaluated,
execution_attempted, order_emitted and decision_eligibility_asserted all remain false.

## Local context and exact replay

Entries bind actual native requirement/version/hash and native common runtime context,
plus hashes of the three new implementation files and this profile's definition.
When admission was observed, entries additionally bind actual window admission/publisher/
bundle source hashes, policy/publication definitions and observed DuckDB version.
The local source reader is bounded to <=1MiB per known implementation file; no whole
repository scanning occurs. These pins are observations under supplied local files,
NOT authenticated interpreter, complete dependency/source-code or issuer attestation.

Replay deliberately requires exact supported current code/runtime context. A code/runtime
change may require explicit future version/lifecycle handling; no silent reinterpretation
or broad cross-runtime replay is introduced. Source edits, line-ending changes or accepted
future repairs can change local context hashes. Replay needs the original supported
context; this @1 is not a recovery/environment-reconstruction system.

Retained refusal replay verifies only stages actually run and frozen policy summaries.
It is not full strategy/decision-loop/execution replay, source acquisition authenticity,
independent availability/economic validity, authority, calendar coverage or permission.

Fresh refusal revalidation re-executes only the original supported gate/point-in-time
policy stages, brackets them with pinned recording reads, and requires exact entry bytes.
Early revalidation still does not probe the unused source. A previously observed source
cannot become absent and still reproduce the original entry. current_publication_checked
only becomes true when actual original admission observations are repeated.

Neither retained replay nor fresh refusal revalidation asserts current native
Bronze/Silver/Gold equality or reads current legacy SQL. The publication admission
reader verifies the archived publication now. Missing current upstream audits may
leave an original refused snapshot reproducible; a missing original publication audit
blocks fresh observation while retained refused-decision replay can remain valid.
current_native_upstream_checked=False is explicit. Repeated agreement is not atomic
cross-database/time truth. There is no positive lane even for unchanged observations.

## Persistence and original obligations

The target is an explicitly initialized empty dedicated native_decisions profile with
actual AuditLedger, not a Gold DatasetContract incorrectly assigned to decision records.
The exact schema/codec/contract definition is retained in its version table. Initialization
is separate; partial initialization cannot be adopted and readers never initialize.

First-write attempt key is profile version plus explicit attempt_id. It excludes
publication/recording pins, request flags/axes, runtime and actor/revision labels.
Changing any of those cannot heal the same failed attempt. A new attempt_id represents
a genuinely new attempt, not adoption/recovery of the old one. Scope is profile-local,
not an independently authenticated global attempt/namespace authority.

Any original decision, attempt link or scoped audit job blocks another write before
source observation. Decision/full entry/materialized refusal result and original attempt
link commit atomically. Domain failure rolls them back but preserves the failed job.
Final SUCCEEDED audit is separate; committed content lacking original audit success is
unreadable and cannot be adopted. No retry/cleanup/supersession or old-good fallback.

Retained reader verifies exact full entry/result/scalars, attempt binding, original job/
config/actor/revision/clock and full three-phase audit, including extra scoped/unlinked
jobs and orphan links. A separately reviewed recording fingerprint binds all recording
clocks/metadata/audit links in addition to the decision content hash. Changed clocks do
not silently satisfy original pins. Application audit integrity is not DB permissions
or a signed trust root against an attacker rewriting storage and supplying new pins.

Caller owns connections. Close writers before readonly reopen. No shared writer or outer
transaction. Public reader enforces actual readonly mode. Late observed source/target
live-file aliases reject without closing the parent. New SQL/tests use quoted actual
catalog.schema.table names, including native_decisions.duckdb/schema collisions.

## Independent bounds

- Complete refusal entry <=262144 bytes.
- Exactly zero or two admission receipts; each <=32768 bytes (aggregate <=65536).
- Hex component/count limits checked before decoding; no partial observation pair.
- One original scoped decision/job/link, with LIMIT overflow checks rather than success filters.
- SQL aggregate count/entry-byte preflight before BLOB transfer plus independent CASE guard.
- Definition <=32768 bytes; bounded metadata identifiers and four-event overflow detection.
- Local implementation source files each <=1MiB, through the accepted bounded hash helper.

All upstream publication/bundle/analytics limits remain unchanged. A source assessment
can still replay a large retained bundle; no streaming or peak-process-memory promise.
No automatic paging, limit inflation, force-eligible fallback, unknown-as-ready or
unbounded artifact transfer is introduced.
